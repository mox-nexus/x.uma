24# x.uma
25
26A matcher engine. You give it a config describing rules and a context describing
27one thing to decide about; it returns the action of the first rule that matches,
28or the `on_no_match` fallback.
29
30The same config runs identically in Rust, Python and TypeScript.
31
32## The evaluation model, in four sentences
33
341. Rules are tried **in order**. The first match wins and evaluation stops.
352. A rule's predicate reads one **input** from the context and compares it.
363. If an input finds no value, the predicate is **false**. That is not an error.
374. If no rule matches, `on_no_match` decides. If there is none, there is no decision.
38
39Point 3 is the most common source of confusion. A missing field never raises;
40it simply fails to match. If a rule "does nothing", check whether the input is
41reading a key that exists.
42
43## Commands
44
45| Intent | Command |
46|---|---|
47| Try a config against a context | `rumi run <config.yaml> --context key=value` |
48| Same, HTTP domain | `rumi run http <config.yaml> --method GET --path /api` |
49| Same, Claude Code hooks | `rumi run claude <config.yaml> --event PreToolUse --tool Bash` |
50| Check a config loads | `rumi check <config.yaml>` |
51| See what inputs exist | `rumi info [http\|claude]` |
52| Read this document | `rumi --skill` |
53| Read a specific reference | `rumi --skill -r config` |
54
55Validate before you evaluate. `rumi check` fails at load with a message; a bad
56config never silently returns a wrong answer.
57
58## Config shape
59
60```yaml
61matcherList:
62  matchers:
63    - predicate:
64        singlePredicate:
65          input:
66            name: method
67            typedConfig:
68              "@type": type.googleapis.com/xuma.kv.v1.MapInput
69              key: method
70          valueMatch:
71            exact: GET
72      onMatch:
73        action:
74          name: read-handler
75          typedConfig:
76            "@type": type.googleapis.com/xuma.core.v1.NamedAction
77            name: read-handler
78
79onNoMatch:
80  action:
81    name: fallback
82    typedConfig:
83      "@type": type.googleapis.com/xuma.core.v1.NamedAction
84      name: fallback
85```
86
87This is canonical protojson — protobuf's own JSON mapping of
88`xds.type.matcher.v3.Matcher`. `@type` selects which input reads the context;
89its sibling fields are that input's own settings. `valueMatch` is how the
90extracted value is compared. An action is a `NamedAction`: its own `name`
91carries the value the engine returns.
92
93Predicates compose: `singlePredicate`, `andMatcher`, `orMatcher`, `notMatcher`.
94
95```yaml
96predicate:
97  andMatcher:
98    predicate:
99      - { singlePredicate: { input: {...}, valueMatch: { exact: "GET" } } }
100      - { singlePredicate: { input: {...}, valueMatch: { prefix: "/api" } } }
101```
102
103`onMatch` is exclusive: it is either an action or a nested matcher, never both.
104
105```yaml
106onMatch: { matcher: { matcherList: { matchers: [ ... ] } } }
107```
108
109## Value matches
110
111| Form | Meaning |
112|---|---|
113| `{ exact: "GET" }` | equal |
114| `{ prefix: "/api" }` | starts with |
115| `{ suffix: ".json" }` | ends with |
116| `{ contains: "admin" }` | substring |
117| `{ safeRegex: { regex: "^/v[0-9]+/" } }` | regular expression, linear time |
118| `ignoreCase: true` | sibling of any of the above; case-insensitive comparison |
119
120Prefer the cheapest form that expresses the rule. `Regex` is RE2-class and safe
121against catastrophic backtracking, but it is still the most expensive option,
122and patterns are length-capped at load.
123
124"#,
125    );
126
127    section(&mut s, "Inputs — test domain", test);
128    section(&mut s, "Matchers — all domains", test_matchers);
129    section(&mut s, "Inputs — http domain (`rumi run http`)", http);
130    section(&mut s, "Inputs — claude domain (`rumi run claude`)", claude);
131
132    s.push_str(
133        r"
134## When a rule does not fire
135
136Work down this list; it is ordered by how often each is the cause.
137
1381. **An earlier rule matched.** First match wins. Run with `--trace` to see which.
1392. **The input read a key that is not in the context.** No value means false.
1403. **A different input than you think.** `rumi info` lists what is registered.
1414. **The config never loaded.** Run `rumi check`. Load failures are loud.
142
143## Limits enforced at load
144
145Nesting depth 32, at most 256 field matchers per matcher, 256 predicates per
146compound, pattern length 8192, regex pattern length 4096. Exceeding one is a
147load error, never an evaluation failure. Evaluation itself cannot fail.
148

163fn section(s: &mut String, title: &str, urls: &[&str]) {
164    let _ = writeln!(s, "## {title}\n");
165    if urls.is_empty() {
166        let _ = writeln!(s, "None registered.\n");
167        return;
168    }
169    for url in urls {
170        let _ = writeln!(s, "- `{url}`{}", hint(url));
171    }
172    s.push('\n');
173}

175/// The config field name each input reads, for inputs that take one.
176///
177/// Every entry is verified against the real loader by `hints_name_real_config_keys`
178/// below: the test builds a config using the key named here and asserts it
179/// loads. A wrong key fails the test rather than shipping in the skill.
180///
181/// This exists because the first version of this file was hand-written and was
182/// wrong about `ToolArgInput` on the day it was written, inside a module whose
183/// doc comment claims these tables cannot drift. The generated half could not.
184/// This half could, and did.
185pub const CONFIG_KEYS: &[(&str, &str)] = &[
186    ("xuma.kv.v1.MapInput", "key"),
187    ("xuma.http.v1.HeaderInput", "name"),
188    ("xuma.http.v1.QueryParamInput", "name"),
189    ("xuma.claude.v1.ToolArgInput", "name"),
190    ("xuma.core.v1.NamedAction", "name"),
191];
192
193/// Prose describing each input, WITHOUT its config key.
194///
195/// The config key comes from [`CONFIG_KEYS`] so it is written once and checked
196/// once. Unknown URLs render bare rather than guessing, so a newly registered
197/// extension appears immediately even before it is described here.
198fn description(type_url: &str) -> &'static str {
199    match type_url {
200        "xuma.kv.v1.MapInput" => "reads the context map",
201        "xuma.core.v1.StringMatcher" => "Exact / Prefix / Suffix / Contains / Regex",
202        "xuma.core.v1.BoolMatcher" => "matches a boolean value",
203        "xuma.http.v1.PathInput" => "request path, without query string",
204        "xuma.http.v1.MethodInput" => "request method",
205        "xuma.http.v1.HeaderInput" => "one header",
206        "xuma.http.v1.QueryParamInput" => "one query parameter",
207        "xuma.http.v1.AuthorityInput" => "`:authority` pseudo-header",
208        "xuma.http.v1.SchemeInput" => "`:scheme` pseudo-header",
209        "xuma.claude.v1.EventTypeInput" => "hook event name, e.g. PreToolUse",
210        "xuma.claude.v1.ToolNameInput" => "tool being invoked, e.g. Bash",
211        "xuma.claude.v1.ToolArgInput" => "one tool argument",
212        "xuma.claude.v1.CwdInput" => "working directory",
213        "xuma.claude.v1.GitBranchInput" => "current git branch",
214        "xuma.claude.v1.SessionIdInput" => "session identifier",
215        _ => "",
216    }
217}

219/// The config key an input takes, if it takes one.
220///
221/// Public so `rumi info --verbose` renders from the same source as `--skill`.
222/// Two copies of this table diverged within hours the last time.
223#[must_use]
224pub fn config_key(type_url: &str) -> Option<&'static str> {
225    CONFIG_KEYS
226        .iter()
227        .find(|(url, _)| *url == type_url)
228        .map(|(_, k)| *k)
229}
230
231/// One-line prose for a type URL, or empty if undescribed.
232#[must_use]
233pub fn describe(type_url: &str) -> &'static str {
234    description(type_url)
235}
236
237/// The rendered hint: prose, plus the config key when the input takes one.
238fn hint(type_url: &str) -> String {
239    let prose = description(type_url);
240    let key = config_key(type_url);
241
242    match (prose.is_empty(), key) {
243        (true, _) => String::new(),
244        (false, Some(k)) => format!(" — {prose}, payload field `{k}`"),
245        (false, None) => format!(" — {prose}"),
246    }
247}

249/// Render a named reference, or `None` if the name is unknown.
250pub fn reference(name: &str) -> Option<&'static str> {
251    match name {
252        "config" => Some(CONFIG_REFERENCE),
253        "authoring" => Some(AUTHORING_REFERENCE),
254        _ => None,
255    }
256}

261const CONFIG_REFERENCE: &str = r#"# Config format
262
263Canonical protojson: protobuf's own JSON mapping of
264`xds.type.matcher.v3.Matcher`. Field names may be written `lowerCamelCase` (the
265canonical form) or the proto's own `snake_case` — both are accepted, a third
266spelling is a load error, and so is a field the schema does not define. That is
267deliberate: a typo in a deny rule must not become a rule that silently never
268fires.
269
270## Top level
271
272```yaml
273matcherList:            # ordered list, first match wins
274  matchers:
275    - predicate: ...
276      onMatch: ...
277onNoMatch:               # optional, used when no rule matched
278```
279
280## Predicates
281
282```yaml
283# singlePredicate: read one input, compare it
284predicate:
285  singlePredicate:
286    input: { name: "...", typedConfig: { "@type": "...", ... } }
287    valueMatch: { exact: "..." }
288
289# andMatcher: every child must match
290predicate:
291  andMatcher:
292    predicate: [ ..., ... ]
293
294# orMatcher: any child matches
295predicate:
296  orMatcher:
297    predicate: [ ..., ... ]
298
299# notMatcher: inverts one child
300predicate:
301  notMatcher: { ... }
302```
303
304Compound predicates evaluate every child even once the outcome is decided. That
305is deliberate: it keeps `--trace` output complete.
306
307## An input's config, and `@type`
308
309`typedConfig` carries an `Any`: `@type` names the message, written as the full
310`type.googleapis.com/xuma.*` URL, and its sibling fields are that message's own.
311A bare name without the prefix is refused, matching what protojson requires
312everywhere else.
313
314```yaml
315input:
316  name: role
317  typedConfig:
318    "@type": type.googleapis.com/xuma.kv.v1.MapInput
319    key: role
320```
321
322## onMatch
323
324Exclusive. An action or a nested matcher, never both.
325
326```yaml
327onMatch:
328  action:
329    name: some-name
330    typedConfig:
331      "@type": type.googleapis.com/xuma.core.v1.NamedAction
332      name: some-name
333
334onMatch:
335  matcher:
336    matcherList:
337      matchers: [ ... ]
338    onNoMatch:
339      action: { name: inner-fallback, typedConfig: { "@type": "...", name: inner-fallback } }
340```
341
342A nested matcher that fails to match does NOT fall back to the parent's next
343rule with a match recorded — the parent continues to its next field matcher.
344
345`keepMatching: true` is a sibling of `action`/`matcher` in xDS. It is not
346implemented — it would record the action and keep evaluating, and this engine
347returns the first match — so it is a load error rather than a silently ignored
348field.
349
350## Actions
351
352`xuma.core.v1.NamedAction` is the action type this engine ships: its `name` is
353the opaque value handed back on match. The engine does not interpret it, and an
354empty name is a load error rather than a rule that fires and returns nothing.
355Mapping an action to behaviour is the caller's job.
356"#;

358const AUTHORING_REFERENCE: &str = r#"# Writing a config from scratch
359
360## 1. Name the decision
361
362Write down the answers before the rules. "Which handler?" gives actions like
363`read-handler`, `write-handler`, `reject`. Actions are opaque names; pick ones
364the calling code can switch on.
365
366## 2. Find the input
367
368```bash
369rumi info            # test domain
370rumi info http
371rumi info claude
372```
373
374Copy the `type_url` exactly. A wrong URL is a load error, not a silent miss.
375
376## 3. Write the narrowest rule first
377
378Order is significant. A broad rule placed first shadows everything after it.
379
380```yaml
381matcherList:
382  matchers:
383    - predicate: { singlePredicate: { input: {...}, valueMatch: { exact: "/api/admin" } } }
384      onMatch: { action: { name: admin, typedConfig: { "@type": "...", name: admin } } }
385    - predicate: { singlePredicate: { input: {...}, valueMatch: { prefix: "/api" } } }
386      onMatch: { action: { name: api, typedConfig: { "@type": "...", name: api } } }
387onNoMatch:
388  action: { name: not-found, typedConfig: { "@type": "...", name: not-found } }
389```
390
391Reversed, `/api/admin` would never be reached.
392
393## 4. Always write on_no_match
394
395Without it, "nothing matched" and "matched nothing useful" are the same result
396to the caller. With it, the fallback is explicit and testable.
397
398## 5. Check, then run
399
400```bash
401rumi check config.yaml
402rumi run config.yaml --context method=GET
403rumi run config.yaml --context method=GET --trace
404```
405
406`--trace` shows every rule considered and why it did or did not fire. Reach for
407it the moment a result surprises you, rather than adding print statements to the
408calling code.
409
410## Common mistakes
411
412| Symptom | Cause |
413|---|---|
414| Rule never fires | An earlier rule matched. Use `--trace`. |
415| Everything falls through | Input reads a key absent from the context. |
416| Load fails on type URL | Typo, or the input belongs to another domain. |
417| Deeply nested config rejected | Depth cap is 32, enforced at load. |
418"#;
