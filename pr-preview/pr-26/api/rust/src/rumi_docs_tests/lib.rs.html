1//! Makes the Rust snippets in `docs/content/` fail the build when they rot.
2//!
3//! The site renders that Markdown; nothing compiled it. Every Rust block was
4//! marked ```` ```rust,ignore ````, which is why four how-to pages could teach
5//! `rumi eval`, `rumi validate` and `register_input` — none of which ever
6//! existed — without anything noticing.
7//!
8//! `#[doc = include_str!(...)]` hands each page to rustdoc, so `cargo test
9//! --doc` compiles its Rust blocks. Blocks marked `no_run` are compiled and not
10//! executed, which is right for snippets that read a config file from disk.
11//!
12//! This crate exists rather than the includes living in `rumi-core` because
13//! `include_str!` needs the file present at build time, and `docs/` is not part
14//! of a published crate's package. Putting them here keeps `cargo publish`
15//! working. It is `publish = false` and has no runtime code.
16
17#![cfg(doctest)]
18
19macro_rules! doc_page {
20    ($name:ident, $path:literal) => {
21        #[doc = include_str!($path)]
22        pub struct $name;
23    };
24}
25
26doc_page!(
27    GettingStartedRust,
28    "../../../docs/content/getting-started/rust.md"
29);
30doc_page!(
31    ConceptsPipeline,
32    "../../../docs/content/concepts/pipeline.md"
33);
34doc_page!(
35    ConceptsTypeErasure,
36    "../../../docs/content/concepts/type-erasure.md"
